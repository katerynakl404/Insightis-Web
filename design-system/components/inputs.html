Input

Single-line text field — 40px tall, ≥16px text to prevent iOS zoom. Shares ds/components/input.css with Textarea and Select. State priority is disabled > error > focus > hover > default. The .ins-input-group rail powers the bottom-CTA newsletter composer (src/components/BottomCTA.jsx).

Default

<input class="ins-input" type="text" placeholder="What metric do you want to unify?">

Sizes

<input class="ins-input ins-input--sm" type="text" placeholder="Small (32px)">
<input class="ins-input" type="text" placeholder="Medium (40px)">
<input class="ins-input ins-input--lg" type="text" placeholder="Large (48px)">

States

Focus and error share the same shape (thin border + wider subtle ring). Disabled goes transparent so it works on any surface.

<!-- default (filled) -->
<input class="ins-input" type="email" value="ceo@acme.com">
<!-- focus (force ring for the specimen) -->
<input class="ins-input" style="border-color:var(--ins-border-focus);box-shadow:var(--ins-focus-ring)">
<!-- error -->
<input class="ins-input is-error" aria-invalid="true">
<!-- disabled -->
<input class="ins-input" placeholder="Disabled" disabled>
<!-- filled + disabled (legible value) -->
<input class="ins-input is-filled" value="Read-only value" disabled>

With leading icon (passive)

Left side is informational only (search / mail glyph) — pointer-events:none passes clicks through to the input.

<div class="ins-input-wrap">
  <span class="ins-input-wrap__icon ins-input-wrap__icon--leading" aria-hidden="true"><svg>…search…</svg></span>
  <input class="ins-input ins-input--with-leading" type="search" placeholder="Search metrics…">
</div>

With trailing action (clear)

Right side is for interactive utilities only (clear / submit). Wired live via data-sb-clearable in storybook.js.

<div class="ins-input-wrap" data-sb-clearable>
  <input class="ins-input ins-input--with-trailing is-filled" type="text" value="Revenue by month">
  <button class="ins-input-wrap__action" type="button" aria-label="Clear"><svg>…×…</svg></button>
</div>

Input group (newsletter composer)

Input + primary button share one rounded rail — the real bottom-CTA form. Submit stays disabled until a valid email (data-sb-validate-email).

<form class="ins-input-group">
  <input class="ins-input" type="email" placeholder="you@company.com" aria-label="Work email">
  <button class="ins-btn ins-btn--primary ins-btn--sm" type="submit">Get started</button>
</form>

Classes

ClassUse
.ins-inputBase field — 40px, card surface, ≥16px text.
.ins-input--sm / --lg32px (14px text) / 48px sizes.
.is-errorError state — red border + red ring; pair with aria-invalid.
.is-filledMarks a field that has a value; keeps text legible when also disabled.
.ins-input-wrapPositioning context for a leading icon or trailing action.
.ins-input--with-leading / --with-trailingAdds padding for the leading icon / trailing action.
.ins-input-wrap__icon--leadingPassive left glyph (search, mail) — non-interactive, dim color.
.ins-input-wrap__actionInteractive trailing button (clear / submit), higher contrast.
.ins-input-groupRounded rail wrapping an input + inner button (newsletter composer).
.ins-input-group.is-error / .is-disabledGroup-level error / disabled treatment.

Usage

The .ins-input-group composer is the real bottom-CTA form in src/components/BottomCTA.jsx (variant="form", placeholder "What metric do you want to unify?"). Bare inputs, leading-icon search, and error/disabled states are built from the input.css API.
