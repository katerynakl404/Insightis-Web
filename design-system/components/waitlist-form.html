Waitlist Form

The single email field on the auth "coming soon" cards. It posts to /api/waitlist and is deliberately not shaped like a login: one type="email" field, no password, the button reads "Join the waitlist" — so Safe Browsing never mistakes it for credential harvesting. Built entirely from inline styles (no .ins-input/.ins-btn); token values are used where the source uses them, with a few literal hex/rgba values kept verbatim from the JSX.

Default (idle, empty)

With no valid address the submit button is disabled: a muted rgba(9,160,157,.18) fill with --ins-color-teal-a-40 text and cursor:default. The label is a small uppercase "EMAIL"; the input sits on a faint white-alpha surface with a 10 px radius.

</form>

Valid (ready to submit)

Once the address passes validation the button becomes active — the teal vertical gradient linear-gradient(180deg,#0EC4C1,#07807E), --ins-text-body text and cursor:pointer. On focus the input border shifts to teal (rgba(14,196,193,.5)).

<!-- valid && !sending -->
<input … style="…border:1px solid rgba(14,196,193,.5);…"> <!-- focused -->
<button type="submit"
        style="…background:linear-gradient(180deg, #0EC4C1 0%, #07807E 100%);
               color:var(--ins-text-body);cursor:pointer">Join the waitlist</button>
<!-- while posting the label becomes "Joining…" and aria-busy is set -->

Error

On a rejected submission the input border turns red (rgba(239,68,68,.5)) and the role="alert" paragraph fills with the matching copy in #F87171. The input is wired to it via aria-describedby.

Please enter a valid email address.

<input … aria-describedby="waitlist-error" style="…border:1px solid rgba(239,68,68,.5);…">
<p id="waitlist-error" role="alert" aria-live="assertive"
   style="…color:#F87171">Please enter a valid email address.</p>

Success (submitted)

When the post succeeds the whole form is replaced by a role="status" confirmation panel on a teal-tinted rgba(9,160,157,0.10) surface with a rgba(9,160,157,0.30) border.
