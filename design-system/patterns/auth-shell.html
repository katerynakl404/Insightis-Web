Auth shell

The page chrome behind the placeholder /auth/sign-in and /auth/sign-up routes, from src/components/AuthShell.jsx + src/components/AuthCard.jsx. A slim sticky top bar carrying the Insightis mark (linked to /) over a single centered "coming soon" card — not a split-screen: auth is not live yet, so there is deliberately no password field or credential input, only the waitlist email capture (src/components/WaitlistForm.jsx). The shell and card are built entirely from inline styles; the source uses no .ins-btn / .ins-input here, so this reproduces the real markup verbatim.

The /auth/sign-in page passes title, blurb and waitlist into AuthCard; /auth/sign-up is identical but with sign-up copy. The card is intentionally not a login: WaitlistForm renders exactly one type="email" field labelled EMAIL, a "Join the waitlist" button, and an off-screen honeypot — no password field, which is what keeps the page clear of Safe-Browsing "deceptive page" heuristics. The submit button starts disabled (empty address is invalid) and the mark is a hand-drawn InsightisMark SVG, not the shared header logo.

Source src/components/AuthShell.jsx (bar + centered slot), src/components/AuthCard.jsx (coming-soon card), src/components/WaitlistForm.jsx (email capture), composed by src/pages/sign-in.jsx and src/pages/sign-up.jsx.
