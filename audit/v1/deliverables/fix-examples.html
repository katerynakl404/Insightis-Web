Concrete "how it should be" for two flagged style defects, using the Insightis design-system tokens. Current (left) vs recommended (right).

1 · Secondary button — default border too faint (AUD-39)

Current border token is --ins-border-default = rgba(255,255,255,0.06) (6% white) on the card surface #131820 — it fails the 3:1 UI-boundary contrast (WCAG 1.4.11) and visually blends. Best practice: a secondary/outline button needs a visible resting border ≥3:1; only the fill/border should *intensify* on hover, not appear from nothing.

Current — border blends in
6% white border ≈ invisible on dark.
Recommended — visible resting border
Give the secondary button its OWN token, not the generic faint border.
/* ds/tokens/colors.css:211 — give the secondary button its OWN token (was var(--ins-border-default) = white 6%) */
--ins-button-secondary-border:       rgba(255,255,255,0.12);  /* toned: visible but not harsh */
--ins-button-secondary-border-hover: rgba(255,255,255,0.24);  /* intensify on hover */
/* consumed by .ins-btn--secondary { border-color } in ds/components/button.css:84 — no change needed there. */

2 · Footer — unbalanced reflow (AUD-40)

There are 5 link groups (Platform, Solutions, Resources, Company, Legal). At 768–1023px .ins-footer__cols is a fixed 3-col grid, so the groups wrap to 3 + 2 — Company & Legal drop to a second row, leaving an empty trailing cell and a large blank area; at ≥1024px justify-content:flex-end pushes the whole row to the right edge. Expected: let the columns flow into an even, gap-free row (auto-fit) with no empty cell and no right-push.
